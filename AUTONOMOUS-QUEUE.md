# Autonomous research queue (LUMEN / lupus nephritis)

Each run: take the FIRST item with status `todo`, set it to `doing`, do it, set it to `done` with a one-line result
and the commit hash, and add any new follow-ups at the end. One item per run unless it finishes early.

## Standing rules (never break)
1. Pre-register (commit a PREREG file) BEFORE looking at the outcome data of any test. State the pass rule.
2. Every model is compared with trivial baselines on held-out data. Report failures as failures.
2b. **Strongest baseline, real FAIL branch (reviewer R-20261123-5, round 126).** Every PREREG's pass rule names the strongest available trivial baseline (carry-forward whenever the patient's or trial's own earlier value exists), and losing to ANY trivial baseline by >= 10% = FAIL, not inconclusive. The clause applies to whatever the decision ships, including the default it falls back to (R-20261124-1, round 132). Template: docs/PREREG-TEMPLATE.md.
3. Label claims Established / Supported / Emerging / Hypothetical. Human data first.
4. Write each round to the claude.ai project as `claude/round-NN-<finding>.md`; push code to branch `rounds-70-72`.
5. Never contact anyone, create accounts, submit forms, or spend money. Never delete data.
6. Research and simulation only. No clinical advice.

12b. **Pre-registration that can be checked (reviewer R-20261123-2, round 124).** A run that writes a PREREG commits and pushes it **and ends** (finish with the usual message; mark the item `[doing: PREREG <hash> pushed; analysis due >= 1 h later]`). Download and analysis happen in a LATER scheduled run, at least 1 hour after the PREREG push. Downloads go through `scripts/provenance/fetch.sh URL OUT MANIFEST.tsv`, which appends fetch UTC time, md5 and HTTP Last-Modified to a manifest committed with the data commit. Every result JSON is written through `scripts/provenance/stamp.py` (adds run_utc, git_head, PREREG commit time). "Verifiably pre-registered" is reserved for tests whose outcome data arrive via `fetch.sh` AFTER the PREREG push (fetch_utc > PREREG commit time, manifest committed). Tests that meet the 1-h rule but run on data already committed (and possibly analysed) before the PREREG are called **"12b-timed (committed data; earlier looks not excludable)"** (reviewer R-20261124-2, round 133; RT-1 and RT-2 are 12b-timed); earlier tests (all rounds up to 122, including those after 111) are "pre-registered, order shown by commit order only". A run that takes a `[doing: PREREG ...]` item whose PREREG is >= 1 h old does the download + analysis.
12. **Sample-size honesty.** Any claim labelled Supported or Established must state n (patients or trials) in the same line.

13. **Daily reviewer (Thomas, 2026-11-23).** An independent reviewer task runs once a day and writes claude/REVIEW-YYYY-MM-DD.md.
