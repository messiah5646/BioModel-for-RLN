# Autonomous research queue (LUMEN / lupus nephritis)

Each run: take the FIRST item with status `todo`, set it to `doing`, do it, set it to `done` with a one-line result
and the commit hash, and add any new follow-ups at the end. One item per run unless it finishes early.

## Standing rules (never break)
1. Pre-register (commit a PREREG file) BEFORE looking at the outcome data of any test. State the pass rule.
2. Every model is compared with trivial baselines on held-out data. Report failures as failures.
3. Label claims Established / Supported / Emerging / Hypothetical. Human data first.
4. Write each round to the claude.ai project as `claude/round-NN-<finding>.md`; push code to branch `rounds-70-72`.
5. Never contact anyone, create accounts, submit forms, or spend money. Never delete data.
6. Research and simulation only. No clinical advice.

## Open-data-only policy (Thomas, 2026-11-22)
Use only data downloadable without an account or a data-use agreement (GEO, CELLxGENE, ArrayExpress/BioStudies, ClinicalTrials.gov,
Zenodo/figshare, paper supplements). ARK/AMP Synapse is ALL controlled (every file carries the ARK controlled AR), ImmPort and dbGaP
need accounts: do not plan around them. When a task needs such data, look for an open substitute or mark it [dropped: not open].

## Decision gate (Thomas, 2026-11-23: "fix it, and keep sanity")
Rounds 91-110 mostly re-confirmed negatives (scVI/Geneformer lose to simple baselines 5x; blood IFN is a set point 5x) or hit
"blocked: not open". From now on:
7. **A run must be able to change a LUMEN decision.** Before starting an item, write one line in the round doc:
   "Decision this can change: <X>. If result A -> do <a>; if result B -> do <b>." If you cannot write that line honestly,
   mark the item `[parked: no decision at stake]` and take the next one. Literature write-ups do not count as decisions.
8. **Do not re-test a settled question.** Settled (do not re-run unless new data type): scVI/Geneformer/PCA embeddings as
   patient-level classifiers (rounds 92, 98, 100, 102, 104); blood IFN as a flare or nephritis marker (rounds 89, 99, 104).
9. **No-op is allowed.** If no PRIORITY item is todo, no gated main-queue item is todo, and no weekly item is due: commit
   nothing, write no round doc, and finish with one line: "Nothing decision-relevant to run; next: <item>."
10. **Audit every 5th round.** Round numbers ending in 0 or 5 are audit rounds (like round 79b): re-check the last 5 rounds'
    load-bearing numbers from the committed code, count how many comparisons were made, downgrade any claim resting on
    n < 10 patients or on a test that was not pre-registered. An audit round that finds nothing wrong says so.
11. **Main stays Thomas's review point.** Never push or merge to main. After each audit round, add one line to
    claude/TODO-for-Thomas-at-the-PC.md: "Audit round NN passed/failed; branch rounds-70-72 is ready/not ready to merge."
12a. **Verifiable pre-registration (round 111).** Push the PREREG, then the data download, then the analysis, as separate commits.
12. **Sample-size honesty.** Any claim labelled Supported or Established must state n (patients or trials) in the same line.

13. **Daily reviewer (Thomas, 2026-11-23).** An independent reviewer task runs once a day and writes claude/REVIEW-YYYY-MM-DD.md. Its `R-...` REVIEWER FLAG items in the PRIORITY queue are taken BEFORE any P item (fix errors before new work). `R-... reviewer minor` and `RT-... REVIEWER ROUTE` items in the main queue are normal gated items. When finishing an R/RT item, say in the round doc whether the reviewer was right; if you disagree, say why with evidence instead of silently skipping it.
